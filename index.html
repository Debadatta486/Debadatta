Audience-first, docs-as-code workflow

I bring documentation into the development cycle early and keep it reviewable, testable, and maintainable.

  1. Start with audience and intent: define the user task, content boundaries, and success criteria before choosing the topic structure.
  2. Design information architecture around user journeys and product concepts so related content is easy to find, scan, and maintain.
  3. Align documentation with product strategy and release plans. Gather facts early from JIRA, specifications, hands-on testing, and SME conversations.
  4. Apply plain-language style standards (MSTP and STE-100), reusable structures, and editorial reviews to keep content consistent across a growing documentation set.
  5. Treat docs as code: author in Markdown, manage changes through GitHub branches and pull requests, and maintain consistency across product and API versions.
  6. Validate UI flows, feature behavior, API endpoints, and sample requests with SMEs, developers, QA, and Postman before publication.
  7. Use AI to accelerate repeatable tasks, with explicit human quality gates for factual accuracy, terminology, tone, hallucinations, and security-sensitive details.
  8. Close the feedback loop: review customer and internal feedback, trace documentation defects to root causes, and improve both the content and the workflow.

How I lead documentation

I connect content strategy, delivery, and quality so documentation supports product outcomes.

Documentation is a product capability, not just a deliverable. I connect content decisions to user needs, product priorities, quality standards, and measurable feedback.

  • Information architecture and content strategy — Organize content around user tasks and product concepts; define what belongs where and reduce duplication.
  • Documentation ownership and alignment — Plan content with product milestones, release scope, and stakeholder priorities.
  • Editorial leadership and quality — Use style standards, peer reviews, technical validation, and clear quality gates to improve consistency.
  • AI-assisted workflows — Apply AI to repeatable tasks while keeping human review accountable for accuracy, terminology, tone, and security.
  • Feedback and continuous improvement — Use customer signals and defect patterns to identify root causes and improve content and process.
  • Standards-aware documentation — Apply relevant documentation standards, including MSTP and STE-100, and aerospace publication standards where applicable.
