Audience-first, docs-as-code workflow

I bring documentation into the development cycle early and keep it reviewable, testable, and maintainable.

  1. Understand the audience and task

    Define who needs the information, what they need to accomplish, and what a successful outcome looks like.

  2. Plan the content structure

    Organize topics around user journeys and product concepts. Define content boundaries and place information where readers expect to find it.

  3. Gather and verify product information

    Review JIRA requirements and specifications, explore the product, test relevant workflows, and resolve open questions with subject-matter experts.

  4. Write and review the content

    Author task-based documentation in Markdown. Apply MSTP and STE-100 conventions, reusable structures, and editorial reviews for clarity and consistency.

  5. Manage changes with GitHub

    Commit updates on a branch, open a pull request, and incorporate peer and technical reviews before merging documentation changes.

  6. Validate examples and workflows

    Check UI instructions, feature behavior, API endpoints, and sample requests with developers and QA. Use Postman to verify API examples where applicable.

  7. Publish and check the output

    Align publication with product releases, then review the rendered documentation to confirm that links, code samples, navigation, and formatting work as expected.

  8. Review feedback and improve

    Use customer and internal feedback to identify content gaps, trace documentation defects to root causes, and improve both the content and the workflow.

How I lead documentation

I connect content strategy, delivery, and quality so documentation supports user needs and product outcomes.

  1. Set the content direction

    Understand user needs, product goals, and audience expectations. Define the documentation strategy, priorities, and success measures before deciding what to write.

  2. Build a clear information architecture

    Organize content around user tasks and product concepts. Define page ownership and content boundaries, make information easy to find, and reduce duplication across the documentation set.

  3. Align documentation with delivery

    Work with Product, Engineering, SMEs, and QA to plan content against feature scope and release milestones. Bring documentation into the development cycle early so it is ready alongside the product.

  4. Establish editorial and technical quality

    Apply style standards such as MSTP and STE-100, and use peer reviews, technical validation, and clear quality checks to maintain accuracy, consistency, and usability.

  5. Use AI responsibly and consistently

    Apply AI-assisted workflows to repeatable tasks such as drafting, restructuring, and terminology checks. Keep human review accountable for technical accuracy, terminology, tone, and security-sensitive content.

  6. Measure feedback and improve

    Use customer feedback, documentation defects, and usage signals to identify content gaps and root causes. Improve both the documentation and the process, and track outcomes where measurable.
