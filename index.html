Audience-first, docs-as-code workflow

  1. Start with the user's task: define the audience and the job they need to get done, then write short, task-based topics.
  2. Work in step with the sprint: gather facts early from specifications, JIRA tickets, hands-on testing, and SME interviews, so documentation ships with the feature.
  3. Write in plain language to a style standard (MSTP, STE-100) and structure reusable content with DITA.
  4. Treat docs as code: draft in Markdown, manage branches, and review changes through GitHub pull requests and code reviews; maintain version consistency across product releases and API versions.
  5. Use automated publishing workflows where available, including static-site generation and CI/CD concepts; validate the published output after deployment.
  6. Validate feature behavior, feature flags, UI flows, API endpoints, and sample requests with SMEs, developers, and QA; check API documentation in Postman.
  7. Use AI tools to speed up repetitive work, then apply editorial review for technical accuracy, current parameters, terminology, brand tone, and security risks.
  8. Publish with each release, trace defects and feedback to their root cause, then fix the content and the process.
